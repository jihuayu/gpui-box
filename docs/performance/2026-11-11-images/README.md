# Decoded image resource evidence

This freezes the [image resource stage](../../RETAINED_IMAGE_RESOURCES.md).
`validation.json` contains 83 successful hardware pixel scenarios, including
16 image cases. Image frames compare incremental output to a fresh full
retained renderer using the same shader and no previous cache. Independent
RGBA/alpha, clip, content-inset and quad-occlusion assertions supplement that
comparison. `image-*.png` files retain the corresponding output.

The normal-click tests verify image replacement through the scoped typed signal,
0 layout/recording for same-sized replacement, changed hardware pixels and
retirement of the old legacy atlas entry. Core coverage reaches 44 tests.
Clippy with `-D warnings` and the desktop build pass.

`metadata.json` records source hashes, compiler/build identity and timing.
All recorded SHA256 values were checked against the measured working tree before
copying this evidence. `adapter.json` identifies GTX 1650 Ti / Vulkan / 571.96.
The recorded base commit precedes this stage; hashes identify its measured code.

`image-benchmark.json` contains 60 measured completed submits per mode and image
size, sorted raw samples, P95, and medians for three rounds with alternating mode
order. Each round/mode has six warmups then twenty samples. Both modes draw the
same decoded bytes at the same translated positions, using full redraw and a
640 × 360 output. A readback outside timing verifies matching pixels per round.

| Texture | Reuse median / P95 | Replace and reupload median / P95 | Median ratio | Texture bytes avoided per frame |
| --- | --- | --- | --- | --- |
| 256 × 256 | 244.0 / 488.8 µs | 457.6 / 772.2 µs | 1.88× | 262,144 |
| 1024 × 1024 | 240.8 / 520.4 µs | 1,404.8 / 1,936.5 µs | 5.83× | 4,194,304 |

Timing includes FramePacket validation, image/quad draw planning, allocation,
bindings, upload, submission and GPU completion. It excludes decoded resource
construction, transaction/layout/snapshot extraction, PNG/readback and native
window presentation. The replacement mode also includes texture/binding
recreation, so this is not an isolated bandwidth benchmark or a comparison to
the full legacy GPUI application lifecycle. Same bytes receive alternating
immutable resource identities in replacement mode; the cache retains only live
identities. Reuse writes image geometry but no texture pixels.

Per-round medians vary (for example 256 reuse: 156.9, 258.4, 389.9 µs), so these
results establish workload-specific upload savings and measured local benefit,
not a universal frame-rate multiplier. The image path still scans full packets
and uses one binding/draw per image. Native texture presentation, batched image
instances and a cross-frame physical GPU budget remain incomplete.

The existing damage/layer benchmark JSON files were also regenerated by the
same runner and are retained for reproducibility. Their workloads are distinct
from this texture-reuse comparison.
