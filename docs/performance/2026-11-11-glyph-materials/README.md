# Independent glyph color materials

This follows the [initial glyph stage](../2026-11-11-glyphs/README.md) on base
commit `acab58b`. A glyph instance now references a stable per-node material
slot. Color updates write 16 bytes per node with no atlas or instance upload.
Adjacent material writes merge; five eight-glyph node updates write 80 bytes
in one range, compared with 2,560 instance bytes in the previous stage. A
450-glyph paragraph changes from 28,800 instance bytes to 16 material bytes.

The slot allocator reuses retired node slots. Its buffer grows geometrically,
rebinds atlas pages and holds old buffer/binding leases through GPU completion.
Queue ordering protects prior submits during writes/reuse. Material changes
invalidate isolated raster content even when geometry/atlas are unchanged.

`validation.json` records 102 passing hardware scenarios including 19 text
cases; additional cases check material-only layer invalidation and slot reuse.
The existing CPU mask-blend oracle, multi-page ordering, batch merge and bounded
in-flight replacements continue to pass. Ten real-font/normal-click tests,
Clippy with `-D warnings` and the desktop WGPU build pass. The core implementation
is unchanged from the 44-test initial stage. Source SHA256 values (45 entries)
were verified before freezing. The adapter remains GTX 1650 Ti / Vulkan 571.96.

The benchmark draws identical 450-glyph output at 800 × 600 with full redraw.
Three rounds rotate three mode orders; each mode has six warmups and twenty
samples per round (60 measured samples). End-of-round pixel readbacks are equal
and outside timing. `text-benchmark.json` retains raw sorted samples and rounds.

| Path | Median / P95 submit + completion | Atlas bytes | Instance bytes | Material bytes |
| --- | --- | --- | --- | --- |
| Warm, material-only color | 361.4 / 620.6 µs | 0 | 0 | 16 |
| Warm, also rewrite instances | 487.9 / 649.9 µs | 0 | 28,800 | 16 |
| Cold GPU atlas/instances/materials | 1,142.9 / 2,089.6 µs | 2,243 | 32,832 | 32 |

The instance-rewrite diagnostic alternates a clip edge beyond the glyph ink.
This changes instance records while retaining the same visible pixels, warm
atlas, material writes and shader. It is an upload-path comparison, not a build
of the old inline-color shader or an exact color-only workload on that shader.
The cold mode additionally includes atlas/buffer allocation and binding work.

The median warm rewrite/material ratio is 1.35× and cold/material ratio is
3.16×. Timing varies materially: per-round material medians are 228.3, 355.0,
542.5 µs; rewrite medians are 421.4, 463.4, 517.9 µs. The last material round
is slightly slower than rewrite. Upload reduction is deterministic; these
samples do not establish a universal latency gain or sustained FPS improvement.

Timing includes full packet validation, glyph planning/comparison, GPU writes,
submit and completion. Resource creation, shaping, rasterization, transaction,
layout/snapshot extraction, reset/pipeline construction, readback and native
presentation are excluded. The extra shader storage lookup is included in
all modes; its independent cost versus inline color has not been measured.

This stage does not remove CPU full-glyph scans or solve rich-text material
runs, property indirection, compaction/pressure fallback, physical GPU budgets
or native presentation. Damage/layer/image benchmark files are regenerated by
the same runner and included as separate reproducible workloads.
